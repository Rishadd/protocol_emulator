# Protocol Emulator — Instruction Reference and Protocol Programs

Companion to the RTL in [src/](src/) and the tests in [tb/](tb/). This is the
contract the host loader must follow when it writes programs into instruction
memory. Anything marked **VERIFIED** has passed simulation (`run_tests.ps1` and the management/duplex testbenches);
UART TX and RX have also run on a DE0-Nano. Anything marked **DRAFT** (SPI, I2C, JTAG) is derived from the same cycle
rules but has not been run on the RTL yet. Status as of 2026-10-11.

---

## 1. Instruction word

```
bit 31       27 26                                    0
    +----------+--------------------------------------+
    |  opcode  |         operand (27 bits, flat)      |
    +----------+--------------------------------------+
word = (opcode << 27) | operand
```

One operand, one meaning per opcode. No sub-fields except `CFG`.

| Opcode | Enc | Mnemonic | Operand | Effect | Cycles |
|---|---|---|---|---|---|
| 0 | `00000` | `NOP` | — | nothing | 1 |
| 1 | `00001` | `WAIT d` | delay | hold PC | d+1 |
| 2 | `00010` | `JMP a` | addr[5:0] | pc ← a | 1 |
| 3 | `00011` | `HALT` | — | halted=1, fault=0 | — |
| 4 | `00100` | `SETL n` | count[15:0] | loop counter ← n | 1 |
| 5 | `00101` | `DJNZ a` | addr[5:0] | loop--; jump to a if result ≠ 0 | 1 |
| 6 | `00110` | `PULL` | — | block until tx_fifo non-empty; OSR ← word | 1 (+wait) |
| 7 | `00111` | `PUSH` | — | block until rx_fifo not full; rx_fifo ← ISR; ISR ← 0 | 1 (+wait) |
| 8 | `01000` | `OUT1 d` | delay | pin[out_pin] ← OSR bit; shift OSR | d+1 |
| 9 | `01001` | `IN1 d` | delay | ISR ← pin_in[in_pin] (shift in) | d+1 |
| 10 | `01010` | `SETH p` | pin[2:0] | pin_out[p] ← 1 | 1 |
| 11 | `01011` | `SETLO p` | pin[2:0] | pin_out[p] ← 0 | 1 |
| 12 | `01100` | `DIRO p` | pin[2:0] | pin_oe[p] ← 1 (drive) | 1 |
| 13 | `01101` | `DIRI p` | pin[2:0] | pin_oe[p] ← 0 (release / input) | 1 |
| 14 | `01110` | `WAITH p` | pin[2:0] | block until pin_in[p]==1 | 1 (+wait) |
| 15 | `01111` | `WAITL p` | pin[2:0] | block until pin_in[p]==0 | 1 (+wait) |
| 16 | `10000` | `CFG v` | see below | shifter / pin routing config | 1 |
| 17–18 | | *(reserved)* | | `WAITR`/`WAITF` edge waits; no longer needed for UART RX (level waits suffice) | trap |
| 19–31 | | *(reserved)* | | | trap |

`CFG` operand: `[2:0]` out_pin, `[5:3]` in_pin, `[6]` OSR MSB-first, `[7]` ISR MSB-first.

**Trap** = `halted=1, fault=1`, PC frozen, no side effects. Only reset clears it.

### Timing rules (VERIFIED in `tb_control_unit` and `tb_engine_top`)

1. Every instruction commits its effect on its **first** cycle.
2. Non-timed instructions take exactly 1 cycle.
3. `WAIT d`, `OUT1 d`, `IN1 d` occupy exactly **d+1** cycles. `d=0` is 1 cycle.
4. Blocking instructions hold the PC with **zero** side effects until the condition clears, then behave as a 1-cycle instruction.
5. Pin outputs change at the end of the commit cycle. Pin inputs seen by `IN1`/`WAITH`/`WAITL` are 2 clocks old (synchronizer).
6. Reset releases every pin (`pin_oe=0`, `pin_out=0`) and clears both FIFOs.

**Consequence for bit-banged periods:** a bit generated by `OUT1 d` followed by `DJNZ` has a period of **d+2** cycles (d+1 for OUT1, 1 for the branch). A bit generated by `SETx` + `WAIT d` also has period d+2. So for any protocol:

```
d = cycles_per_bit − (number of 1-cycle instructions in the bit loop) − 1
```

### Shifter conventions

| Mode | OSR (`PULL` then `OUT1`) | ISR (`IN1` then `PUSH`) |
|---|---|---|
| LSB-first (`CFG[6]/[7]=0`) | host writes byte in `[7:0]`; bit 0 goes out first | after 8× `IN1`, byte sits in `[31:24]` |
| MSB-first (`CFG[6]/[7]=1`) | host writes byte in `[31:24]`; bit 31 goes out first | after 8× `IN1`, byte sits in `[7:0]` |

## 2. UART TX — **VERIFIED** (`tb_engine_top` B6, B7, B8)

8N1, LSB-first, one pin. Pin map: `pin 0` = TX.

```
addr  mnemonic       hex (D=432, 115200)  hex (D=5206, 9600)   note
 0    CFG   0x00     80000000             80000000             out_pin=0, LSB-first
 1    DIRO  0        60000000             60000000             drive TX
 2    SETH  0        50000000             50000000             idle high
 3    PULL           30000000             30000000             <- loop entry, blocks for host byte
 4    SETL  8        20000008             20000008             8 data bits
 5    SETLO 0        58000000             58000000             start bit
 6    WAIT  D        080001B0             08001456
 7    OUT1  D        400001B0             40001456             <- data bit (loop body)
 8    DJNZ  7        28000007             28000007
 9    SETH  0        50000000             50000000             stop bit
10    WAIT  D        080001B0             08001456
11    JMP   3        10000003             10000003
```

**Baud math** (50 MHz clock): bit period = D+2 cycles.

| Baud | cycles/bit | D | D hex | actual baud | error |
|---|---|---|---|---|---|
| 115200 | 434 | 432 | `0x1B0` | 115207 | +0.006% |
| 57600 | 868 | 866 | `0x362` | 57604 | +0.006% |
| 38400 | 1302 | 1300 | `0x514` | 38402 | +0.005% |
| 19200 | 2604 | 2602 | `0xA2A` | 19201 | +0.005% |
| 9600 | 5208 | 5206 | `0x1456` | 9601 | +0.006% |

For a different clock: `cycles_per_bit = round(f_clk / baud)`, `D = cycles_per_bit − 2`.
Only words 6, 7, 10 change with baud.

**Verified waveform properties:** start and all 8 data bits are exactly D+2 cycles;
stop-to-next-start gap is exactly D+5 cycles when the FIFO already holds the next
byte (`SETH`+`WAIT`+`JMP`+`PULL`+`SETL`), longer otherwise. Engine parks at
address 3 with the line high when the FIFO is empty.

**Host procedure:**
1. Reset, load the 12 words, release reset.
2. Write bytes to `tx_fifo` (`tx_wr_en`, `tx_wr_data[7:0]`); 4-deep, check `tx_full`.
3. Nothing else — the engine loops forever. `pc==3` means idle/waiting for data.

**Important:** `SETL` must come *before* `SETLO` (start bit). Placing it between
`WAIT` and the first `OUT1` stretches the start bit by 1 cycle (found and fixed
before the first simulation).

## 2b. UART RX — **VERIFIED** (`tb_de0_nano_rx_top`, `tb_mgmt_read`, `tb_mgmt_duplex`; also on the DE0-Nano)

8N1, LSB-first, no stop-bit/framing check. Pin map: `pin 1` = RX (`in_pin=1`). Generated by
`host/uart_rx_prog.py` into `src/fpga/uart_rx_prog.hex`. Level waits only: no edge-detect opcode is needed.

```
addr  mnemonic       hex (D=432, 115200)  note
 0    CFG   0x08     80000008             out_pin=0, in_pin=1, LSB-first
 1    WAITH 1        70000001             <- loop entry; wait for line idle (see below)
 2    WAITL 1        78000001             block until start bit
 3    SETL  8        20000008             8 data bits
 4    WAIT  W        08000287             to the middle of data bit 0, W = round(1.5*(D+2)) - 4
 5    IN1   D        480001B0             <- sample data bit (loop body)
 6    DJNZ  5        28000005
 7    PUSH           38000000             ISR -> rx_fifo, clear ISR
 8    JMP   1        10000001             next byte
```

Bit period = D+2 cycles (`IN1 D` + `DJNZ`). Words 4 and 5 change with baud (`W`, `D`).
After 8 x `IN1` LSB-first the byte sits in **bits [31:24]** of the RX FIFO word (the host shifts it down).
Tolerates about -4.5 % / +6 % of peer baud error.

**Reset trap:** the input synchronizer resets to 0, so just after reset an idle line looks like a start bit and corrupts the
first frame (samples land ~200 cycles off centre). The program therefore waits for the line to be **high** (word 1) before
waiting for the start bit. This is fixed in firmware only; the RTL is unchanged.

**Host procedure:** load the 9 words, run, then pop `rx_fifo` whenever it is not empty. Over the management link that is
a read of `base+0x204` after STATUS shows data ([docs/MGMT_PLAN.md](docs/MGMT_PLAN.md)).

## 3. SPI master, mode 0 (CPOL=0, CPHA=0), 8-bit, MSB-first — **DRAFT**

Full duplex: one `OUT1` and one `IN1` per bit. Pin map: `2`=SCLK, `3`=MOSI, `4`=MISO, `5`=CS.

```
addr  mnemonic       hex          note
 0    CFG   0xE3     800000E3     out_pin=3, in_pin=4, OSR+ISR MSB-first
 1    DIRO  2        60000002     SCLK
 2    DIRO  3        60000003     MOSI
 3    DIRI  4        68000004     MISO is input
 4    DIRO  5        60000005     CS
 5    SETLO 2        58000002     SCLK idle low
 6    SETH  5        50000005     CS idle high
 7    PULL           30000000     <- loop entry; host writes byte<<24
 8    SETLO 5        58000005     CS active
 9    SETL  8        20000008
10    OUT1  H        40000000|H   MOSI <- bit, low half of SCLK
11    SETH  2        50000002     SCLK rise
12    IN1   H        48000000|H   sample MISO, high half of SCLK
13    SETLO 2        58000002     SCLK fall
14    DJNZ  10       2800000A
15    SETH  5        50000005     CS inactive
16    PUSH           38000000     ISR -> rx_fifo (byte in [7:0])
17    JMP   7        10000007
```

**Clock math:** bit period = 2H+5 cycles (OUT1 H+1, SETH 1, IN1 H+1, SETLO 1, DJNZ 1).
SCLK high phase = H+2, low phase = H+3 (1-cycle asymmetry, harmless for SPI).
At 50 MHz: H=20 → 45 cycles/bit → 1.11 MHz; H=5 → 15 cycles → 3.33 MHz;
H=0 → 5 cycles → 10 MHz (upper limit of this loop structure).

**Known caveat to verify:** `IN1` at word 12 samples the *synchronized* MISO, which is
2 clocks old — i.e. the value MISO had 2 cycles before SCLK rose. Slaves drive MISO
on the falling edge, so this is fine when H ≥ 2. For H < 2 move `IN1` after `SETLO 2`
(sample after the falling edge) and re-derive the period.

**Host:** write `byte << 24` to `tx_fifo`; read `rx_rd_data[7:0]` from `rx_fifo` once
per byte (`rx_empty` low). CS toggles per byte; for multi-byte transactions with CS
held low, move words 8 and 15 outside a second `SETL`/`DJNZ` loop.

## 4. I2C master write — **DRAFT, needs one ISA addition**

Pin map: `6`=SDA, `7`=SCL. Open-drain is done in firmware: `pin_out` is preset to 0
once, then **`DIRO` = drive low, `DIRI` = release (high via pull-up)**. `WAITH 7`
after releasing SCL handles clock stretching for free.

Primitive sequences (each `WAIT t` sets the quarter-period `t`):

```
init:        SETLO 6 ; SETLO 7 ; DIRI 6 ; DIRI 7          both released, idle
START:       DIRO 6 ; WAIT t ; DIRO 7                      SDA low while SCL high, then SCL low
STOP:        DIRO 6 ; WAIT t ; DIRI 7 ; WAITH 7 ; WAIT t ; DIRI 6
bit=0:       DIRO 6 ; WAIT t ; DIRI 7 ; WAITH 7 ; WAIT t ; DIRO 7 ; WAIT t
bit=1:       DIRI 6 ; WAIT t ; DIRI 7 ; WAITH 7 ; WAIT t ; DIRO 7 ; WAIT t
ACK slot:    DIRI 6 ; WAIT t ; DIRI 7 ; WAITH 7 ; IN1 0 ; WAIT t ; DIRO 7 ; PUSH
```

**Gap:** `OUT1` writes `pin_out`, so it cannot express "release for 1 / drive-low for 0"
and a data byte would have to be unrolled as 8 hand-written bit sequences (too many
words). Proposed fix before implementing I2C: a `CFG` bit **`[8] OUT1 open-drain`**
that makes `OUT1` write `pin_oe[out_pin] ← ~bit` instead of `pin_out`.

> **Update 2026-10-11:** the preferred fix is now a **per-pad open-drain mode in the planned pin-management block**
> (pad data forced 0, pad enable = `oe & ~out`), which needs no ISA change; `OUT1`/`SETH`/`SETLO` then behave as
> open-drain on that pad. That block is only a prototype (see [docs/ASIC_AREA_AND_MEMORY_STUDY.md](docs/ASIC_AREA_AND_MEMORY_STUDY.md) §5),
> so the gap stays open in the RTL. The `CFG` bit below is the fallback if the pin manager is dropped.

With the open-drain `OUT1`, a
data bit is `OUT1 t ; DIRI 7 ; WAITH 7 ; WAIT t ; DIRO 7` and the byte fits in a
`SETL 8`/`DJNZ` loop like UART/SPI. The ACK is captured with `IN1` into the ISR and
pushed to the host, who decides retry/abort (no conditional branch on a pin exists
yet; `BR_PIN` is a candidate for v0.5).

## 5. JTAG (Shift-IR / Shift-DR) — **DRAFT**

Reuses the SPI pins: `2`=TCK, `3`=TDI, `4`=TDO, `5`=TMS. TMS is driven by `SETH/SETLO`
between shift loops to walk the TAP state machine; the shift loop itself is the SPI
loop with TMS held low, LSB-first (`CFG 0x23`: out_pin=3, in_pin=4, both LSB-first).

```
shift N bits (TMS=0):
 SETL  N
 OUT1  H       TDI <- bit (TCK low)
 SETH  2       TCK rise    (target samples TDI)
 IN1   H       capture TDO (drove on previous TCK fall)
 SETLO 2       TCK fall
 DJNZ  <OUT1>
```

The last bit of a shift must have TMS=1 to exit Shift-xR: run the loop for N−1,
then `SETH 5` and one more unrolled bit. Chains longer than 32 bits are streamed by
the host: `PULL` every 32 bits, `PUSH` every 32 bits — the engine never needs to know
the chain length. TAP-walk sequences (Test-Logic-Reset → Run-Test/Idle → Select-DR →
Capture → Shift) are pure `SETH/SETLO 5` + `SETH/SETLO 2` pairs.

## 6. What the host loader needs

| Capability | Used by | Exists in RTL today |
|---|---|---|
| Write 64×32 instruction memory while engine held | all | **yes** — `imem_we/waddr/wdata`, accepted only while `run`=0; over SPI at `base+0x100+4i` (simulation) |
| Start/stop an engine without resetting FIFOs or memory | all | **yes** — `run` input; SPI `base+0x000` bit 0 |
| Write `tx_fifo` (32-bit words) | all | yes (`tx_wr_en/tx_wr_data/tx_full`); SPI `base+0x200` |
| Read `rx_fifo` | SPI, I2C ACK, JTAG | yes (`rx_rd_en/rx_rd_data/rx_empty`); SPI `base+0x204` |
| Assert/release reset | all | yes |
| Read `pc`, `halted`, `fault` | debug | yes; SPI `base+0x000` read |
| Read back instruction memory | verify after load | **no** (flop memory has no read port for the host; becomes possible with SRAM) |
| Per-protocol pin idle levels | all | firmware, not host — every program's init block sets them |

Every program above starts at address 0 with its own `CFG` + `DIRx` + idle-level init,
so switching protocol is: stop the engine (`run`=0) → load new words → start it (reset also works). No shared state
survives between programs except the physical pull-ups.
