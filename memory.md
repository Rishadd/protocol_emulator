# Project Memory: UART on the Protocol Emulator (DE0-Nano + HC-05)

> **Historical log** (UART and the first engine phases, up to 2026-10-17). Current status: [docs/EXECUTION_PLAN.md](docs/EXECUTION_PLAN.md), all results: [docs/TEST_RESULTS.md](docs/TEST_RESULTS.md), documentation map: [docs/README.md](docs/README.md).

**Idea:** a programmable protocol engine (21-opcode ISA, 256-word program memory since 2026-10-17 (was 64), FIFOs, 8 pins). UART is *firmware* running on it, not dedicated hardware. Target board: DE0-Nano at 50 MHz, talking to a phone through an HC-05 Bluetooth module.

## How we verified (same recipe for TX and RX)
Python "fake phone" generates the waveform -> real RTL simulated in Icarus -> Python compares what came out. Only after that did we compile in Quartus and program the board. Nothing went to the FPGA unverified.

## Problems and fixes
1. **Fake start bit at reset (RX).** The input synchronizer resets to 0, so the idle line looked like a start bit and corrupted the first frame. Showed up as samples sitting ~200 cycles off-centre. Fixed in firmware only: wait for the line to be high before waiting for the start bit.
2. **Byte position.** With LSB-first shifting the received byte lands in bits [31:24] of the FIFO word, not [7:0]. The LED sink reads [31:24].
3. **Tools.** Icarus 0.9.7 could not build the testbenches; upgrading in place left a stale 32-bit DLL (vvp crashed with 0xC000007B). Fixed by overwriting `C:\iverilog` with a clean v12 install. Quartus is not on PATH (`C:\intelFPGA_lite\20.1\quartus\bin64`), and `python` is a Store stub (use the global 3.12).
4. **Quartus compile once ran without the clock constraint** ("SDC not found", transient). Re-ran; always check timing slack after a compile (RX: +12 ns setup, 0 errors).

## Decisions made
- No stop-bit/framing check in RX (kept simple). RX tolerates phone baud error of about -4.5% / +6%.
- LEDs just show the last received byte.
- Each build is its own Quartus revision (`protocol_emulator_fpga` = TX, `protocol_emulator_rx` = RX), so a working bitstream is never broken.
- Engine RTL was never changed; all fixes were firmware or new small modules.

## Key files
`src/fpga/uart_tx_prog.hex`, `src/fpga/uart_rx_prog.hex` (generated by `host/uart_rx_prog.py`), `src/rx_led_sink.v`, `src/fpga/de0_nano_rx_top.v`, `host/uart_workload.py` (TX checks), `host/uart_rx_workload.py` (RX checks), `tb/`, `run_tests.ps1`.

## Why TX and RX can't just share one engine
One engine runs one program, and the ISA has no "check and branch" instruction: RX blocks waiting for a start bit, TX blocks waiting for data. So the TX and RX builds are separate bitstreams today.

## SPI master + slave (DONE 2026-10-11, simulation only, no FPGA)
Design: [docs/SPI_PLAN.md](docs/SPI_PLAN.md). Results: [docs/SPI_RESULTS.md](docs/SPI_RESULTS.md). Run: `python host/spi_test.py`.
- Decisions: add a pin-conditional jump; no loopback yet; 1-32 bits per CS frame.
- **ISA:** `JPH p,a` (17) / `JPL p,a` (18), operand `[8:6]` pin, `[5:0]` addr, 1 cycle. `tb_control_unit` traps moved to 19/20;
  `tb_fetch_equiv` draws illegal opcodes from 19-31 (now 21-31; note: tb/ref/ref_engine.v shares src/control_unit.v,
  only its fetch path is frozen, so PUSHI is kept out of its random programs: the reference RX FIFO has no immediate path).
- Firmware from `host/spi_prog.py`: master 17/18 words, slave 18/16 words (CPHA 0/1). Slave polls CS in every edge wait,
  so CS inactive mid-frame aborts cleanly (no PUSH). CPHA=0 slave ends at the last sample (CS may rise right after the last edge).
- Master timing exact in all modes: lead H+2, idle H+3, CS setup H+2 clocks. Master samples MISO 1 clock before its own
  edge -> peer clock-to-out < H+1 clocks (measured: H=4 passes 40 ns, fails 50 ns).
- Slave limits (clocks): half >= 4 (CPHA0) / 5 (CPHA1); CS setup >= 6 / 1; CS high >= 4. Samples 1-3 clk after the edge,
  MISO 3-5 clk after the shift edge, released 3 clk after CS rises. Host must preload TX and drain RX (failures are detected).
- Chip level: sustained slave needs ~2 management frames per SPI frame (25 us OK, 20 us fails at 10-clk mgmt half period).
- Testbench lessons: (1) X->0 at reset is not an SCLK edge (decoder counts only 0<->1); (2) chip tb pads need `assign #1`
  to filter the zero-width `uio_out` mux pulse (same lesson as UART); (3) a slave answering a whole half-period late still
  passes data checks with a slow peer, so the slave's sample/response time is now a checked limit; (4) CS setup must
  mean CS fall to first edge in the master model, else the sweep never stresses it.
