# Project Memory: UART on the Protocol Emulator (DE0-Nano + HC-05)

**Idea:** a programmable protocol engine (17-opcode ISA, 64-word program memory, FIFOs, 8 pins). UART is *firmware* running on it, not dedicated hardware. Target board: DE0-Nano at 50 MHz, talking to a phone through an HC-05 Bluetooth module.

## Where we are (as of 2026-10-08)
| Step | Result |
|---|---|
| UART TX firmware (12 words) | Matched a Python reference cycle-exactly at 8 baud rates, then worked on the FPGA: phone received the message |
| UART RX firmware (9 words) | Verified in simulation, then worked on the FPGA: byte sent from phone shows on the 8 LEDs |

## How we verified (same recipe for TX and RX)
Python "fake phone" generates the waveform -> real RTL simulated in Icarus -> Python compares what came out. Only after that did we compile in Quartus and program the board. Nothing went to the FPGA unverified.

## Problems and fixes
1. **Fake start bit at reset (RX).** The input synchronizer resets to 0, so the idle line looked like a start bit and corrupted the first frame. Showed up as samples sitting ~200 cycles off-centre. Fixed in firmware only: wait for the line to be high before waiting for the start bit.
2. **Byte position.** With LSB-first shifting the received byte lands in bits [31:24] of the FIFO word, not [7:0]. The LED sink reads [31:24].
3. **Tools.** Icarus 0.9.7 could not build the testbenches; upgrading in place left a stale 32-bit DLL (vvp crashed with 0xC000007B). Fixed by overwriting `C:\iverilog` with a clean v12 install. Quartus is not on PATH (`C:\intelFPGA_lite\20.1\quartus\bin64`), and `python` is a Store stub (use the global 3.12).
4. **Quartus compile once ran without the clock constraint** ("SDC not found", transient). Re-ran; always check timing slack after a compile (RX: +12 ns setup, 0 errors).

## Decisions made
- No stop-bit/framing check in RX (kept simple). RX tolerates phone baud error of about -4.5% / +6%.
- LEDs just show the last received byte.
- Each build is its own Quartus revision (`protocol_emulator_fpga` = TX, `protocol_emulator_rx` = RX), so a working bitstream is never broken.
- Engine RTL was never changed; all fixes were firmware or new small modules.

## Key files
`src/fpga/uart_tx_prog.hex`, `src/fpga/uart_rx_prog.hex` (generated by `host/uart_rx_prog.py`), `src/rx_led_sink.v`, `src/fpga/de0_nano_rx_top.v`, `host/uart_workload.py` (TX checks), `host/uart_rx_workload.py` (RX checks), `tb/`, `run_tests.ps1`.

## Why TX and RX can't just share one engine
One engine runs one program, and the ISA has no "check and branch" instruction: RX blocks waiting for a start bit, TX blocks waiting for data. So the TX and RX builds are separate bitstreams today.

## SPI management link (simulation only, started 2026-10-11)
Plan: [docs/MGMT_PLAN.md](docs/MGMT_PLAN.md). Steps 1-8 from the user's list.
- Baseline before changes: all unit tbs PASS. `tb_de0_nano_top` hangs (pre-existing, FPGA-only, not touched); left out of runs.
- **Step 1 DONE.** `instr_mem` got a sync write port (`we/waddr/wdata`), read stays combinational. `tb_instr_mem` PASS (fill/readback, we=0, isolation, read-during-write, back-to-back, INIT_FILE overwrite). Mutations caught.
- **Step 2 DONE.** New `spi_slave` (mode 0, 2-flop sync, byte stream), minimal `mgmt` (exactly 4 bytes -> eng0 word 0 on CS_N rise), `tt_um_protocol_emulator` top (TT pins: ui_in[0..2]=SCLK/MOSI/CS_N, uo_out[0]=MISO, uio=engine pins). `engine_top` got `imem_*` ports; old instantiations tied off. `tb_spi_word0` PASS: write lands 3 clocks after CS_N rise, 1-cycle strobe, SCLK 8-50 clk/half, bad lengths dropped, reset mid-frame. VCD: build/tb_spi_word0.vcd.
- Regression after steps 1-2: 12 tbs PASS.
- **Step 3 DONE.** Frame v1 = 7 bytes `{op, addr[15:0], data[31:0]}`, MSB first, big endian (deviation from doc's little endian: frame = one plain shift register). op 0x01 WRITE. `0x1000` ENG0_CTRL bit0 RUN, `0x1100+4i` eng0 word i. `engine_top` got `run`: run=0 holds PC/control/counters/shifters/pins in reset (pins released), FIFOs+memory kept. RUN resets to 0. Imem writes only while RUN=0, else rejected + sticky `err`. `tb_mgmt_frame` PASS (replaces tb_spi_word0). Mutations caught.
- **Step 4 DONE.** No RTL change needed (1 frame = 1 word). `tb_mgmt_load`: full 64-word loads over SPI then RUN; golden engine loaded by $readmemh runs in lockstep (PC/pins every clock). Pattern, 64-word, UART TX and RX images: 15,679 cycles, 0 mismatches.
- **Step 5 DONE.** Engine 1 added: `0x2000` ENG1_CTRL, `0x2100+4i` eng1 words (`addr[15:12]` = engine). Shared write bus, per-engine `we`/RUN. Pads: `uio_oe = oe0|oe1`, engine 0 wins a shared pin (no ownership regs yet). `tb_mgmt_dual` PASS: only-0, only-1, both interleaved, TX/RX both ways round, load one while other runs, stop/restart one, pin conflict, 9 bad addresses. Two golden engines in lockstep, ~112k cycles, 0 mismatches. Mutations caught.
- **Step 6 DONE.** READ (op 0x02) on MISO in the same 7-byte frame: MISO = `{STATUS, 00, 00, data}`. STATUS (free every frame) = `[7]1 alive [6]err [5:4]RUN [3:2]tx_full [1:0]rx has data`. `base+0x204` RX_DATA (pops), `base+0x000` CTRL read = `{pc, fault, halted, RUN}`. Read data frozen after byte 2; pop only on complete frame and only if that frame's STATUS said data (no torn/lost bytes). `tb_mgmt_read` PASS with real UART RX firmware: in-order 4-deep, empty read, abort, byte arriving mid-read, both engines, SCLK sweep, MISO never changes while SCLK high. 6 mutations caught.
- Bug caught while writing: read decode must use `frame[23:0]` (op+addr position after 3 bytes), not final positions.
- **Step 7 DONE.** `base+0x200` TX_DATA write -> engine TX FIFO (also while RUN=0 = preload). Accepted only if this frame's STATUS showed tx_full=0, else dropped and host resends (no err). `tb_mgmt_tx` PASS with real UART TX firmware: 101 bytes decoded on P0, 0 framing errors, golden engines in lockstep; 64-byte stream with 218 flow-control resends, preload-then-RUN, aborted write, engine 1 TX, SCLK sweep.
- **Step 8 DONE.** `tb/tb_mgmt_duplex.v` + `host/mgmt_duplex_stress.py`. Host model loads TX prog -> eng0 (P0) and RX prog -> eng1 (P1) over SPI, RUN both, then one loop does TX writes + RX reads using STATUS. P1 = live echo peer (sends each byte back as soon as received) or replay (pass 1 records P0 to file, pass 2 sends file back). Python decodes both lines with the reference receiver and compares sent / tx_rec / echo_rec / rx_spi (files in build/mgmt_duplex/<case>/). 1 KB, 115200: ideal, SPI 13.3 clk, peer +-2%, jitter 20 ns, replay ideal, replay -1.5% + 15 ns jitter: all 1024/1024, every TX frame cycle-exact, 0 faults/err. Negative (host stalls 12 byte-times, replay keeps sending): loss detected (247/256, first bad 99).
- Full regression (16 tbs) PASS on final RTL.
- Testbench lesson: UART receiver models must sample on clock edges. The pad mux (`uio_out` depends on `oe0`) makes a zero-width sim glitch when a pin is enabled; an edge-triggered model mistook it for a start bit.

## ASIC area study (2026-10-11, analysis only, no src/ change)
Full write-up: [docs/ASIC_AREA_AND_MEMORY_STUDY.md](docs/ASIC_AREA_AND_MEMORY_STUDY.md). Tools live outside the repo: Yosys etc. in `C:\tools\oss-cad-suite` (OSS CAD Suite 2026-10-10), CMOS5L liberty in `C:\tools\ihp-cmos5l`, SRAM macro views in `C:\tools\ihp-sram`. Run `synth/run_synth.sh <tag> [VAR=val]` from the repo root (bash).
- Whole chip on real CMOS5L cells: **414,137 um^2, 15.5k cells = 57.5% of the 720k nominal**; the two flop instruction memories are 80% of it. Library has no plain DFF (cheapest flop 49 um^2).
- SRAM instead (4 x 1P 64x16): **143k (20%)**. 2P 256x32 shared with page select: ~182k (25%, estimate). Single-port macro cannot serve two engines.
- Blocker to confirm with organizers: `sg13cmos5l_sram` in the PDK is a symlink to the SG13G2 macros; CMOS5L acceptance unproven.
- Pin ownership block prototype: 5.2k um^2 (0.7%); with remap 14.7k. Also makes open-drain an ownership mode, so no ISA bit needed for I2C.
- After SRAM the 4 FIFOs are the next big item (41k). Not yet done: SRAM fetch simulation, STA, pin_mgr simulation.

## SRAM instruction memory (DONE 2026-10-11, simulation only)
Write-up with all numbers: [docs/SRAM_INSTR_MEM_RESULTS.md](docs/SRAM_INSTR_MEM_RESULTS.md).
- `instr_mem` = 2 x IHP 1P 64x16 macros per engine (same address; u_lo = bits 15:0, u_hi = bits 31:16). Read is synchronous, so `pc_reg` outputs `next_pc` and `engine_top` addresses imem with it: instr is still the word for the current pc. ## SPI master + slave (DONE 2026-10-11, simulation only, no FPGA)
Design: [docs/SPI_PLAN.md](docs/SPI_PLAN.md). Results: [docs/SPI_RESULTS.md](docs/SPI_RESULTS.md). Run: `python host/spi_test.py`.
- Decisions: add a pin-conditional jump; no loopback yet; 1-32 bits per CS frame.
- **ISA:** `JPH p,a` (17) / `JPL p,a` (18), operand `[8:6]` pin, `[5:0]` addr, 1 cycle. `tb_control_unit` traps moved to 19/20;
  `tb_fetch_equiv` draws illegal opcodes from 19-31 (the reference engine predates JPH/JPL).
- Firmware from `host/spi_prog.py`: master 17/18 words, slave 18/16 words (CPHA 0/1). Slave polls CS in every edge wait,
  so CS inactive mid-frame aborts cleanly (no PUSH). CPHA=0 slave ends at the last sample (CS may rise right after the last edge).
- Master timing exact in all modes: lead H+2, idle H+3, CS setup H+2 clocks. Master samples MISO 1 clock before its own
  edge -> peer clock-to-out < H+1 clocks (measured: H=4 passes 40 ns, fails 50 ns).
- Slave limits (clocks): half >= 4 (CPHA0) / 5 (CPHA1); CS setup >= 6 / 1; CS high >= 4. Samples 1-3 clk after the edge,
  MISO 3-5 clk after the shift edge, released 3 clk after CS rises. Host must preload TX and drain RX (failures are detected).
- Chip level: sustained slave needs ~2 management frames per SPI frame (25 us OK, 20 us fails at 10-clk mgmt half period).
- Testbench lessons: (1) X->0 at reset is not an SCLK edge (decoder counts only 0<->1); (2) chip tb pads need `assign #1`
  to filter the zero-width `uio_out` mux pulse (same lesson as UART); (3) a slave answering a whole half-period late still
  passes data checks with a slow peer, so the slave's sample/response time is now a checked limit; (4) CS setup must
  mean CS fall to first edge in the master model, else the sweep never stresses it.
