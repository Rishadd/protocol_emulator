## 1. Goal and scope

The chip acts as an **I2C master (controller)** and as an **I2C slave (target)**:
- 7-bit addressing;
- **100 kHz (Sm), 400 kHz (Fm) and 1 MHz (Fm+)**;
- write, read and combined (repeated START) transactions;
- ACK/NACK handling;
- clock stretching in both directions;
- the host reaches the chip only through the existing management SPI link.

Out of scope for now:
- multi-master arbitration;
- 10-bit addressing;
- Hs-mode;
- SMBus timeouts and PEC;
- loopback between the two engines;
- FPGA.

## 2. Decisions (2026-10-11)

| # | Decision | Effect on this plan |
|---|---|---|
| D1 | RTL may change if it enables more protocols, but **the engine must stay protocol agnostic** | No I2C-specific logic anywhere in the engine or the chip |
| D2 | New instructions are allowed only if they are **fundamental and reusable** by other protocols | Two generic opcodes: `JPO` (branch on data bit) and `PUSHI` (push an immediate). See §5 |
| D3 | **Build the pin manager** | Pin ownership plus per-pad open-drain mode. Open-drain is an electrical pad property, not an ISA feature. See §4 |
| D4 | **The host decides the slave address match** | The slave pushes the address byte and stretches SCL until the host answers ACK or NACK. No compare logic in firmware |
| D5 | Speeds 100 kHz / 400 kHz / 1 MHz | The generator takes the speed and the system clock and computes the delays |
| D6 | Logic minimal and clean; no FPGA; no work outside this task | Pin manager without diagnostic owner and without REMAP. Engine RTL changes kept to a few lines |
| D7 | Chip-level testbenches (§4.4) are updated and re-run **after** the I2C implementation, not during Phase 0b | Phase 0b verifies the pin manager with its own unit tb only |
| D8 | **Do not implement the I2C slave now** (it does not fit comfortably in 64 words, §6.4.1) | Phases 4 and the slave half of 5 are on hold; the master proceeds |

## 3. Design principles

1. **The engine knows nothing about I2C.**
   - Open-drain lives in the pad layer (pin manager).
   - I2C framing lives in firmware generated by `host/i2c_prog.py`.
   - Decisions (address match, read length, STOP) live in the host.
2. **Every new instruction must have at least two uses outside I2C.** They are listed with each opcode in §5.
3. **One uniform 9-bit byte slot** for reading and writing, in both roles (§6.2). This removes every read/write branch from firmware.
4. **Clock stretching is the flow control.**
   - The slave holds SCL low at every byte boundary while it does `PULL`/`PUSH`, so it can never lose data when the host is slow. This differs from the SPI slave.
   - The master parks with SCL low while waiting for the host, which is legal.
5. **Nothing drives a pad unless the host has claimed it** (pin manager reset state).

## 4. Pin manager (new module `src/pin_mgr.v`)

### 4.1 Function
Starts from the area-study prototype `synth/experiments/pin_mgr.v`, simplified.

| Feature | Kept? | Reason |
|---|---|---|
| Owner per pad: none / engine 0 / engine 1 | **yes** | Isolation, so a later-loaded protocol cannot steal a pin from a running one |
| Claim refused while the pad's current owner is running | **yes** | Same rule as instruction loads (only while RUN=0) |
| Per-pad open-drain mode: pad data forced 0, pad enable = `oe & ~out` | **yes** | Makes `SETH`/`SETLO`/`OUT1` I2C-safe with no ISA change; also serves 1-Wire, SMBus, PS/2 |
| Sticky per-engine violation bits (a non-owner enabled a pad) | **yes** | Cheap, catches host misconfiguration (architecture V03) |
| Diagnostic owner (host drives pads) | no | Not needed now; owner code 3 is reserved and refused |
| REMAP (pad ↔ engine pin maps) | no | Not needed now (+9.5k um² in the study) |
| `& run` gating of the drive mux | no | Already guaranteed: a held engine resets its pins (`engine_top`, verified). Run is used only by the claim rule |

**Pad equations** (p = 0..7, s = owner of p):
```
oe_sel  = (s==1) ? oe0[p]  : (s==2) ? oe1[p]  : 0
out_sel = (s==1) ? out0[p] : (s==2) ? out1[p] : 0
uio_oe[p]  = od[p] ? (oe_sel & ~out_sel) : oe_sel
uio_out[p] = od[p] ? 0                   : out_sel
viol0[p] |= oe0[p] & (s != 1)        viol1[p] |= oe1[p] & (s != 2)
```
- **Inputs:** both engines keep reading every pad (`uio_in`). Ownership limits only driving, as in architecture §5.
- **Open-drain firmware idiom:** `DIRO p` once (enable), then `SETH p` / `OUT1 1` release the line and `SETLO p` / `OUT1 0` pull it low.
- **Reset:** owner = none, od = 0, viol = 0. Nothing drives.

### 4.2 Management registers (window `0x0200`, as in the architecture register table)

| Address | Write | Read |
|---|---|---|
| `0x0200 + 4p`, p = 0..7 | `data[1:0]` owner (0 none, 1 eng0, 2 eng1), `data[2]` open-drain. **Refused** (sticky `err`, no change) if the pad's current owner is running, if owner = 3, or if any other bit is set | `{29'd0, od[p], owner[p]}` |
| `0x0220` | write-1-to-clear violation bits: `data[7:0]` eng0, `data[15:8]` eng1 | `{16'd0, viol1, viol0}` |

The other `0x02xx` addresses keep today's behaviour for unmapped addresses (`err`).

### 4.3 Integration
- **`tt_um_protocol_emulator`:** the `oe0|oe1` / "engine 0 wins" merge is replaced by `pin_mgr`.
- **`mgmt`:** gets the `0x0200` decode, a write strobe, a read mux entry and a `refused` input that sets `err`
  (as built: 9 ports, 2 decode wires, 4 read-mux lines, 4 commit lines). `pin_mgr` synthesizes to 3,680 um^2.
- **No change to** `engine_top`, `pin_block` or `spi_slave`.

### 4.4 Effect on existing tests (required, mechanical)

With owner = none at reset, **every chip-level testbench that watches `uio` must claim its pads before RUN**: `tb_mgmt_frame`, `tb_mgmt_load`, `tb_mgmt_dual`, `tb_mgmt_read`, `tb_mgmt_tx`, `tb_mgmt_duplex` and `tb_spi_chip`.

- **These are pin-manager regressions, not UART feature work.** They are re-run once to prove nothing broke.
- **Untouched:** engine-level testbenches and every FPGA file (the FPGA tops use `engine_top` directly, not the TT top).

## 5. ISA additions (generic)

| Opcode | Mnemonic | Operand | Effect | Cycles |
|---|---|---|---|---|
| 19 | `JPO a` | `[5:0]` addr | **Jump if the next OSR output bit is 1**; OSR shifts by one either way (the bit is consumed) | 1 |
| 20 | `PUSHI v` | `[26:0]` value | **Push the immediate `v` (zero-extended to 32 bits) into the RX FIFO**; blocks while the FIFO is full; ISR untouched | 1 (+wait) |

**`JPO`: branch on a data bit.** This is the only way for host data to steer firmware. Other uses:
- per-word command flags for any protocol (SPI keep-CS / release-CS, UART send-break);
- JTAG TMS sequences streamed from the host;
- 1-Wire reset vs bit slots;
- selecting a parity or stop-bit variant per frame.

It reuses existing signals: `osr_bit` → `pc_jump`, `osr_shift`.

**`PUSHI`: report an event or status code to the host.** Other uses:
- UART framing-error or break marker;
- SPI "frame aborted by CS" marker (today the abort is silent);
- JTAG state markers;
- any protocol's "transaction done".

It needs a 2-way mux on the RX FIFO write data (ISR vs operand) in `engine_top`.

**RTL size (as built, Phase 0a):**
- `isa.vh`: 2 defines.
- `control_unit`: 1 port (`push_imm`), the PUSHI stall term, 2 decode cases (11 lines).
- `engine_top`: 1 wire and 1 mux line on the RX FIFO write data.

**Test changes these cause:**
- `tb_control_unit`: JPO/PUSHI unit tests; trap tests move to opcodes 21/22.
- `tb_fetch_equiv`: random illegal opcodes drawn from 21–31. `tb/ref/ref_engine.v` shares `src/control_unit.v` (only its
  fetch path is frozen) but its RX FIFO has no immediate path, so PUSHI is kept out of the random programs.
- New `tb_engine_ops`: JPO and PUSHI inside a real `engine_top` (added to `run_tests.ps1`).

**Event word convention** (host side only, not hardware):
- PUSHI codes always set bit 26 (`0x4000000 | code`).
- Bus data words are at most 9 bits wide, so the two can never collide.

| Code | Name | Pushed by |
|---|---|---|
| `0x4000001` | START (or repeated START) seen | slave |
| `0x4000002` | STOP seen | slave |
| `0x4000003` | NACK: transfer stopped, queued words skipped | master |

## 6. I2C design

### 6.1 Pins and electrical
- **Pins:** 6 = SDA, 7 = SCL, the same for both roles. The host claims both pads for the engine with **open-drain = 1**.
- **Pull-ups** are external; in simulation they are a wired-AND bus model with a configurable rise time (§7.2).
- **Init in every program:** `SETH 6`, `SETH 7` (released), then `DIRO 6`, `DIRO 7`. From then on `SETLO` and `OUT1 0` pull low, and `SETH` and `OUT1 1` release.

### 6.2 The 9-bit slot (used by both roles)

On I2C, sending a 1 means releasing SDA. So **reading a byte is sending 0xFF while sampling SDA**, and the ACK bit is the 9th bit of the same slot.

| Byte | Bits driven (9) | Bits sampled (9) |
|---|---|---|
| Master write | data[7:0], `1` (release for the slave's ACK) | data echo, slave ACK (0) or NACK (1) |
| Master read | `0xFF`, `0` = ACK or `1` = NACK (last byte) | slave data, own ACK bit |
| Slave receive | `0xFF`, `0` = ACK or `1` = NACK | master data, own ACK bit |
| Slave transmit | data[7:0], `1` | data echo, master ACK (0) or NACK (1) |

- **Per bit:** drive SDA from OSR (`OUT1`) while SCL is low, let SCL go high, sample SDA (`IN1`) while SCL is high.
- **After 9 bits:** the ISR holds `{data[7:0], ack}` in `[8:0]` (MSB-first).
- **Arbitration hint:** the echo shows any bit pulled low by someone else. It is free; it is reported, not acted on.

### 6.3 Master firmware (`i2c_prog.master(speed, f_clk)`)

**TX word (one per byte, MSB-first, flags interleaved in OSR shift order):**

| Bits | Field | Meaning |
|---|---|---|
| `[31]` | S | Generate START before this byte (repeated START if a transfer is open) |
| `[30:22]` | slot | 9 bits to drive (§6.2) |
| `[21]` | C | Check ACK: if the sampled 9th bit is 1 (NACK) → STOP, `PUSHI 0x4000003`, then skip queued words until one with S=1 |
| `[20]` | P | Generate STOP after this byte |

**RX word per byte:** `[8:0] = {sampled data[7:0], sampled ack}`.

**Structure (as built: 46 words; the estimate of 32 was low):**
```
init     : CFG (out=SDA, in=SDA, MSB-first) ; release both ; DIRO both ; WAITH SCL ; WAITH SDA (bus idle)
next     : PULL ; JPO -> start ; (no START)
slot     : SETL 9 ; bit loop:  SETLO SCL ; OUT1 (SDA) ; WAIT tLOW ; SETH SCL ; WAITH SCL (stretch/rise) ;
                               IN1 tHIGH ; DJNZ           (SCL is released high at loop end)
after    : JPO -> check                      (C flag; SCL is still high in the 9th bit, SDA = ACK)
back     : SETLO SCL ; PUSH ; JPO -> stop ; JMP next
check    : JPH SDA -> nack ; JMP back       (branch on the live ACK level while SCL is high)
stop     : SETLO SDA ; SETH SCL ; WAITH SCL ; WAIT tSU;STO ; SETH SDA ; WAIT tBUF ; JMP next
start    : (SCL low or idle) SETH SDA ; SETH SCL ; WAITH SCL ; WAIT tSU;STA ; SETLO SDA ; WAIT tHD;STA ; -> slot
nack     : stop ; PUSHI 0x4000003 ; skip: PULL ; JPO -> start ; JMP skip
```
- The exact ordering (where the C check samples, and SCL low before PUSH) is fixed when the program is written. Its timing is checked by the decoder.
- **Parked state:** PULL with SCL low inside a transfer (legal pause), or with the bus idle after STOP.
- **Timing:** each delay is `ceil(t_min · f_clk)` plus a margin clock. `WAITH SCL` measures high time from when SCL is really high, so slow rise and stretching are absorbed.

### 6.4 Slave firmware (`i2c_prog.slave(f_clk)`, *estimate ≤ 50 words*)

| State | Behaviour |
|---|---|
| **idle** | Wait until SCL and SDA are both high, then wait for SDA to fall while SCL is high (= START). `PUSHI START` |
| **address** | Receive 8 bits with SDA released, sampling on SCL high. At SCL low after bit 8: **hold SCL low**, `PUSH` the address word (`[7:0]` = addr7 + R/W), `PULL` the host's decision word, drive its `[31]` as the ACK bit, release SCL |
| **after ACK slot** | If the 9th bit sampled 1 (NACK, from either side): release SDA, go to **wait-end** |
| **byte** | Hold SCL low, `PULL` the slot word, release SCL, then run the 9-bit slot. At the **first bit only**, while SCL is high: SDA rising = STOP (`PUSHI STOP` → idle), SDA falling = repeated START (`PUSHI START` → address). Otherwise continue. At the end, hold SCL low, `PUSH {data, ack}`, release |
| **wait-end** | SDA released; wait for STOP or START, push the event, go to idle or address |

- **Why only the first bit:** a legal master issues STOP or repeated START only where the next byte's first bit would be. A bus error in the middle of a byte is recovered by the host (RUN 0 → 1, which is tested).
- **Stretching:** SCL is held low only at byte boundaries and only for the clocks the `PULL`/`PUSH` takes. When the host is slow, that is the clock stretch.
- **Sync latency:** the slave sees SCL fall about 2–3 clocks late, then drives SDA. The SDA change is safely after SCL low (t_HD;DAT ≥ 0 is met) and well inside t_VD;DAT (450 ns at 1 MHz ≈ 22 clocks at 50 MHz).

#### 6.4.1 Why the slave does not fit (paper count, 2026-10-11)

The ≤ 50-word estimate above was optimistic. A block-by-block count of the §6.4 design:

| Block | Words | What it holds |
|---|---|---|
| Init | 5 | CFG, release SDA/SCL, enable both pads |
| Idle: wait for START, report it | 5 | 4 poll words (SCL high, SDA high, then SDA falls while SCL stays high) + `PUSHI` |
| Address: 8 bits | 6 | wait SCL low after START, `SETL`, loop (wait high, `IN1`, wait low, `DJNZ`) |
| Address decision by the host (D4) | 5 | hold SCL, `PUSH` address, `PULL` decision, drive ACK bit, release SCL |
| Address ACK slot | 3 | wait high, branch on NACK, wait low |
| Byte start | 5 | hold SCL, `PULL` slot word, `SETL`, drive bit 1, release SCL |
| First bit with STOP / repeated-START watch | 8 | sample, then two poll paths: SDA was 0 (watch rise = STOP), SDA was 1 (watch fall = Sr) |
| Bits 2..8 loop | 5 | drive, wait high, sample, wait low, `DJNZ` |
| ACK bit, unrolled for the NACK branch | 5 | drive, wait high, sample, branch on NACK, wait low |
| Byte end | 2-3 | hold SCL, `PUSH`, loop |
| NACK path | 5 | wait low, hold SCL, `PUSH`, release SDA and SCL |
| Wait-end (after NACK): watch STOP / Sr again | 7-8 | the same two-path watch as the first bit |
| STOP and Sr events | 4 | `PUSHI` + jump, twice |
| **Total** | **~64-67** | **limit: 64 words** (2 x 64x16 SRAM per engine) |

The master needs only ~30 words, because it *generates* SCL and never watches for START/STOP. The slave is bigger for five
structural reasons:
1. **No subroutines.** The "watch SDA while SCL is high for STOP / repeated START" sequence (~7 words) is needed in three
   places (idle, first bit of every byte, after a NACK) and has to be copied each time.
2. **A change of SDA needs two code paths.** `JPH`/`JPL` test one pin at one level, and there is no "wait for change";
   so "SDA was 0, watch for a rise" and "SDA was 1, watch for a fall" are separate poll loops.
3. **One loop counter, but two special bits.** The first bit (STOP/Sr watch) and the ninth (NACK branch) must sit
   outside the `DJNZ` loop, so the bit body appears three times.
4. **The address byte is different** (host decides mid-byte, D4), so it has its own loop and ACK slot.
5. **Every edge costs a word.** Each bit needs two polled edge waits; there is no combined "wait edge, then sample".

That leaves no room for timing tweaks, so the slave is deferred (D8). Generic ways to make it fit, for a later decision:

| Option | Saves | Generic? | Cost |
|---|---|---|---|
| `CALL a` / `RET` with a one-entry return register | ~10-14 words (watch block written once) | yes: any protocol with repeated sequences (UART/SPI/JTAG bit routines) | ~10 RTL lines + a 6-bit register |
| Drop repeated-START detection at the first bit (STOP only) | ~4 words | n/a (feature cut) | host-visible limitation |
| 128-word instruction memory (4 macros per engine) | +64 words | yes | area: 2 more SRAM macros per engine |

### 6.5 Host procedures

**Master:**
1. Claim pads 6 and 7 (owner = the engine, od = 1).
2. Load the program and RUN.
3. Per transaction, queue words:
   - address word with S=1, C=1;
   - write data words with C=1;
   - read words carry `0xFF` and ACK = 0, except the last, which carries NACK = 1;
   - the last word has P=1;
   - a repeated START is just S=1 on a later address word.
4. Read one RX word per byte, plus a `0x4000003` event if a NACK ended the transfer.

**Slave:**
1. Claim pads 6 and 7, load the program, RUN.
2. Read RX words:
   - **START event, then the address word** → decide; write a decision word with `[31]` = 0 (ACK) or 1 (NACK).
   - **Master writing** (R/W = 0) → for each byte write `0xFF` + ACK (or NACK to refuse), and read the `{data, ack}` words.
   - **Master reading** (R/W = 1) → for each byte write `data + 1`; the `ack` field of each RX word says whether the master wants more.
   - **STOP / START events** end or restart the transaction.

**Host rules (documented and tested):**
- **TX FIFO empty at each START.**
- **In slave-transmit, at most one unconsumed TX word.** The master decides the read length, so preloading more would leave stale words after its NACK.
- **Rule breaks show up as data errors, not hangs:** the slave always stretches instead of losing data.

## 7. Verification

### 7.1 Method (same as SPI)
- **Data and programs:** Python generates the data and the programs.
- **Simulation:** the RTL runs in Icarus against independent Verilog peers.
- **Logging:** the testbench logs every SDA/SCL change, the per-pad drive state of the chip, ISR shift times and FIFO words.
- **Checking:** an independent Python decoder (it knows only the I2C spec, not the firmware) rebuilds the transactions, checks every timing parameter and compares the data end to end.
- **Case types**, as in SPI:
  - **PASS cases** must pass;
  - **"expect fail" cases** must be detected;
  - **sweeps** report limits;
  - **mutants** must be caught.

| File (new) | Role |
|---|---|
| `src/pin_mgr.v` | pin manager (§4) |
| `host/i2c_prog.py` | master/slave program generator, word builders, event codes |
| `host/i2c_test.py` | runner: phases, reference waveform, decoder, checks, sweeps, mutants |
| `tb/i2c_peer.vh` | bus model + Verilog master model + slave model(s) + logger |
| `tb/tb_pin_mgr.v` | pin-manager unit test |
| `tb/tb_i2c_engine.v` | `engine_top` + `pin_mgr` + direct FIFO host |
| `tb/tb_i2c_chip.v` | full chip; host only through the management link |

### 7.2 Bus model
- **Wired-AND:** `line = 0` if the chip pad or any peer pulls low, else 1 after the pull-up rise delay. In Verilog this is a continuous assign with separate rise and fall delays, e.g. `#(t_rise, 0)`.
- **Open-drain check:** the chip must never actively drive SDA or SCL high. Violation: `uio_oe=1` and `uio_out=1` on pads 6 or 7.
- **Zero-width pulses:** the 1 ns inertial pad delay (SPI lesson) still applies on the chip harness.

### 7.3 Peers (written from the spec, not from the firmware)
- **Slave model:**
  - 7-bit address;
  - ACKs its address, NACKs others;
  - write buffer and read data;
  - optional NACK after k data bytes;
  - clock stretch none / at each byte / at each bit / long (ns parameter);
  - its own t_VD;DAT delay;
  - a second instance at a different address for multi-slave tests.
- **Master model:**
  - START, address + R/W, write N, read N (NACK on the last byte), repeated START, STOP;
  - speed parameter with t_LOW/t_HIGH and setup/hold values;
  - optional jitter;
  - waits for SCL to really be high (respects stretching);
  - optional bus error (STOP in the middle of a byte).

### 7.4 Decoder checks
- **Bus conditions:** START, repeated START and STOP detection. Any other SDA change while SCL is high is a violation.
- **Bytes:** bits are read at SCL rising edges, giving the byte and the ACK; transactions are rebuilt as address, R/W, data and ACKs.
- **Timing:** every §6.6 parameter for the selected speed, using the measured min and max over the whole run, plus SCL frequency ≤ the nominal speed.
- **Open-drain:** the open-drain rule above, and that only owned pads are driven.
- **End-to-end data:**
  - host TX → bus → peer;
  - peer → bus → host RX;
  - event words in the right places;
  - no extra or missing bytes.

| **4 Engine = slave** | slave program; host model decides the address | own address ACK / foreign NACK, write, read with master NACK on last, repeated START, STOP after every byte position, back-to-back transactions, slow host (stretching, no loss), RX not drained (stretching, no loss), bus error mid-byte + RUN recovery, 3 speeds, 1 KB stress; master-speed sweep to find the slave limit | no lost or extra bytes, events in order, t_VD;DAT and hold within spec, SDA released after NACK |
| **5 Full chip** | both roles on both engines through the management link, pads claimed via `0x0200` | the Phase 3/4 matrix in reduced form, 256-byte stress per role, throughput measured, management `err` = 0, a claim attempt on a running engine's pad refused | all pass, violation bits 0 in valid runs |
| **6 Mutants + docs** | `i2c_test.py mutants` | firmware: push-pull instead of open-drain (pad not claimed open-drain), sample on SCL low, no STOP detection, no C check, flags out of order, missing stretch at the address phase; pin manager: od ignored, owner ignored | every mutant detected |

### 7.6 Negative cases (must be detected, or handled without loss where stated)
- **Detected:**
  - wrong or absent slave address;
  - speed or timing outside spec (sweeps);
  - SDA stuck low (master `WAITH` waits forever → host timeout + RUN recovery);
  - missing pull-up (line never high → timeout);
  - pad not claimed (nothing on the bus);
  - claim refused while running (`err`);
  - host breaking the §6.5 rules.
- **Handled with no data loss:** a slow host and an undrained RX FIFO, because of clock stretching.
