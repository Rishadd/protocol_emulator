# Progress report, 2026-10-18 to 2026-10-20

Written for the project owner and anyone who reviews the project. Covers the three busiest days: flows, architecture changes, tests, the logic analyser, errors found and how they were fixed, and what is open. Dates are 2026; times are local. The chronological project log with every file name is [../memory.md](../memory.md); every test number is in [TEST_RESULTS.md](TEST_RESULTS.md); how to repeat the results is in [../reproduce/README.md](../reproduce/README.md).

## 1. Summary in ten lines
1. The chip is now a **two-engine programmable protocol processor with 28+ instructions, a CRC unit, an ALU, remappable pins, a line coder for USB, a safe management link (frame v2) and a shared 512-word instruction memory**. 13 protocols run as firmware and are verified in simulation against independent models.
2. **Physical design:** the best layout of the shared-memory chip (run **sh8**) reaches **19.64 ns at the slow corner = 50.9 MHz**, LVS clean, 0 DRC, +0.36 ns slack at a real 20 ns clock. It took a tight 17 ns constraint and moving one gate into the engines; every other idea tried (repair after routing, delay synthesis, margins) did not pay.
3. **8x4 tiles** are needed (6x4 did not route once pin mapping and the line coder were added); a three-column floorplan routes cleanly.
4. **Logic analyser Phases 1-3 are built and verified**: model, capture unit, `TSTAMP` opcode, engine trigger line, register window, interrupt, debug view, host helper and a chip-level test through the real SPI link. It is not in any layout yet.
5. **Verification grew**: 47-suite regression on `main`; a 57-suite regression on the shared branch; 6 formal proofs; every planted-bug (mutant) set caught (38/38 engine, 20/20 frame v2, 16/16 shared memory, 12/12 analyser).
6. Real bugs found by this testing: a duplicated TX byte after the frame v2 merge, a power-grid short with the 2-port macro, a routing failure of the 6x4 floorplan, and a dozen test-harness bugs (all fixed).
7. The work moved from Windows/WSL to **native Ubuntu**; a `reproduce/` kit now repeats every result, and a flow rerun matched the original in all 29 completed steps.
8. GitHub: the base design passed the official gds/precheck/gl_test jobs (run 39250627497). A check branch with the current shared-memory chip was pushed on 10-20 evening; its result is on GitHub's Actions page.
9. Documents: user guide draft with 47 figures, six new plans, a competitor review, a TODO list and this report.
10. Not done: logic analyser Phases 4-8 (engine debug, sniffers, formal proofs of the analyser, layout with its macro, host tool), mutation campaign, timing checker, FPGA demos, final freeze (12-13).

## 6. The logic analyser (Phases 1-3)
**What it does.** Records what 16 channels did, one clock at a time, with triggers, and lets the host read the recording over the management link and turn it into a VCD file for GTKWave.
**Channels.** 0-7 = `uio[7:0]`, 8-12 = `ui_in[7:3]` (after a 2-flop synchroniser, so a capture shows what the firmware would see), 13/14 = RUN of engine 0/1, 15 = OR of the engines' trigger lines (a firmware marker, also usable as a software trigger).
**Modes.** Change mode (default): one 32-bit word per change `{value[15:0], delta[15:0]}`, with an overflow word every 65,535 quiet clocks. Sample mode: every N clocks four 8-bit samples per word (selectable channels 7:0 or 15:8). Ring buffer of 256 words in a third SRAM macro (1P 256x32); the oldest words are overwritten, the trigger position is kept.
**Triggers.** Manual, pattern (mask/value), rising edge, falling edge, software (channel 15 rises), with a post-trigger word count and/or clock count.
**New instructions.** `TSTAMP rd` reads the 32-bit free-running counter; `RPUT TRIG` drives the engine's trigger line (low while the engine is held).
**Register window 0x0300 (frame v2 for the buffer read-out):** `CTRL` (arm, manual trigger; read = state, full, wrapped, write pointer, trigger position), `CONFIG` (mode, sample channels, trigger type, trigger channel), `PATTERN`, `DIV`, `POST`, `TRIGCNT`, `PTR`, `DATA` (buffer word at PTR, then PTR+1; BUSY while capturing), `TS` (the counter). Config writes are refused while a capture runs. Interrupt: IRQ status bit 8 = capture done (to `uo_out[1]`); debug view 6 shows armed / triggered / done / full / wrapped / marker.
**Verification.**
- Model `host/la_model.py` (decoder, VCD writer/reader, self-test with 300 random captures).
- Capture unit `src/la_unit.v` vs the model clock by clock (`host/la_rtl_test.py`): 200 tests x 3000 clocks, depth 16, plus long captures for the overflow word; **12/12 planted bugs caught**.
- Chip level (`host/la_chip_test.py`, through the real SPI link): register reset values and read-back; refusals (reserved bits, trigger type 5, window word 9, read-only TS, config write while capturing, DATA read while capturing = BUSY, v1 DATA read refused); a capture of known pin activity: values 0, 8, 9, B with clock spacing exactly 30 and 20; 4 words for 3 post words, trigger word at index 1; done interrupt on `uo_out[1]` and its clear; view 6; VCD round trip; sample mode (all words 0xA5A5A5A5); TSTAMP difference 11 equal to the model; `RPUT TRIG` shows on channel 15 for exactly 32 clocks and is the software trigger; trigger line low when the engine is held. **All pass.**
- Formal proofs of the blocks the integration touched (pin manager, management, engine, region request): all still pass.
**Limits and what is missing.** Not yet in a layout (no placement for the third macro; fallback is a 32x32 flip-flop buffer); no engine debug (halt, step, breakpoint, read-back), no sniffers, no formal proofs of the analyser's own properties, no `la_capture.py` host tool or GTKWave demo yet. These are Phases 4-8 of [DEBUG_LA_PLAN.md](DEBUG_LA_PLAN.md).
